## 1. Overview

PRIVGUARD AI uses **Alembic** with asynchronous SQLAlchemy for schema versioning and database migrations.

In production environments, the application web workers (`uvicorn app.main:app`) do **NOT** execute `Base.metadata.create_all()`. Instead, schema updates must be applied exclusively via the dedicated `migrate` container or the Alembic CLI before the backend boots.

## 3. Database Roles & Privileges

To ensure tenant isolation cannot be subverted:
1. **Migration Role (`privguard_migrator`)**:
   - Executes DDL: `CREATE TABLE`, `ALTER TABLE`, `DROP TABLE`, `CREATE INDEX`.
   - Executes RLS configuration: `ALTER TABLE ... ENABLE ROW LEVEL SECURITY`, `CREATE POLICY ...`.
   - Never used by the application runtime.
2. **Runtime Application Role (`privguard_app`)**:
   - Executes DML only: `SELECT`, `INSERT`, `UPDATE`, `DELETE`.
   - Strictly forbidden from `SUPERUSER`, `CREATEDB`, `CREATEROLE`, or `BYPASSRLS`.
   - Bound to row-level security policies filtering on `app.current_tenant_id`.

## 4. Operational Commands

### Checking Current Migration Version
```bash
docker compose run --rm migrate alembic current
```

### Upgrading to Latest Head
```bash
docker compose run --rm migrate alembic upgrade head
```

### Creating a New Migration Revision
When changing SQLAlchemy models in `backend/app/database/models.py`:
```bash
# Generate autogenerated revision script
docker compose run --rm migrate alembic revision --autogenerate -m "describe_changes"
```

Inspect and verify the generated file in `backend/alembic/versions/` before committing.

### Rolling Back One Revision
```bash
docker compose run --rm migrate alembic downgrade -1
```
