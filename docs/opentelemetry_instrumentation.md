## 1. Overview & Objectives

PRIVGUARD AI implements end-to-end distributed tracing across the API gateway, agent security layer, memory encryption engine, and external tool connectors using the standard OpenTelemetry Python SDK.

The design enforces strict boundaries:
- **Trace Context Propagation**: W3C `traceparent` and `tracestate` headers are extracted on ingress and propagated across asynchronous boundaries.
- **Span Naming Standards**: Standardized hierarchical naming conventions reflect security enforcement layers.
- **Safe Attribute Filtering**: Dynamic values are validated against `SAFE_ATTRIBUTE_ALLOWLIST`. Any attribute matching `PROHIBITED_KEY_PATTERNS` is dropped.
- **Sanitized Exception Recording**: Exceptions captured during span execution record only exception class names and sanitized error messages. Raw connection strings, tokens, and database credentials are fully scrubbed.

## 2. Trace Context Propagation

### 2.1 Request Correlation Identifiers
Every incoming HTTP request or agent transaction is assigned a correlation context managed via `app.observability.correlation`:
1. `pg_req_<uuid16>`: A unique request ID generated if not supplied via `X-Request-ID`.
2. `Trace ID`: A 128-bit hex string extracted from `traceparent` or generated by the OTel Tracer.
3. `Span ID`: A 64-bit hex string representing the active unit of execution.

```python
from app.observability.correlation import (
    get_request_id,
    get_trace_id,
    get_span_id,
    set_correlation_context,
)

# Context is automatically initialized by ObservabilityMiddleware
request_id = get_request_id()  # Returns 'pg_req_a1b2c3d4e5f6...'
```

### 2.2 W3C Trace Context Standard
Ingress requests parse headers compliant with the W3C Trace Context Level 1 standard:
```
traceparent: 00-4bf92f3577b34da6a3ce929d0e0e4736-00f067aa0ba902b7-01
```
Outbound calls (to MCP servers, LLM backends, or downstream microservices) inject these headers to maintain distributed trace continuity.

## 3. Span Hierarchy & Naming Conventions

All spans generated within PRIVGUARD follow the `privguard.<subsystem>.<action>` format:

| Span Name | Subsystem | Purpose |
| :--- | :--- | :--- |
| `privguard.http.request` | HTTP Middleware | Top-level span for incoming HTTP requests. |
| `privguard.gateway.process` | AI Gateway | Complete lifecycle of prompt/completion inspection. |
| `privguard.privacy.evaluate` | Privacy Engine | PII detection, redaction, and policy enforcement. |
| `privguard.security.threat_detect` | Threat Analysis | Prompt injection scanning and jailbreak heuristics. |
| `privguard.agent.tool_execute` | Agent Core | Tool capability check, approval gating, and execution. |
| `privguard.memory.encrypt` | Memory Vault | Envelope encryption and DEK derivation. |
| `privguard.kms.operation` | KMS Provider | Key wrapping, unwrapping, or rotation. |
| `privguard.canary.run` | Canaries | Synthetic security test execution. |

## 4. Semantic Attributes & Privacy Filtering

### 4.1 Strict Allowlist
Only keys listed in `SAFE_ATTRIBUTE_ALLOWLIST` are allowed into span attributes:

```python
SAFE_ATTRIBUTE_ALLOWLIST = {
    # HTTP
    "http.method", "http.status_code", "http.route", "http.flavor", "http.user_agent_category",
    # Gateway & Privacy
    "privguard.action", "privguard.entity_count", "privguard.pii_detected", "privguard.redacted",
    "privguard.policy_action", "privguard.rule_name", "privguard.detection_engine",
    # Threat & Security
    "privguard.threat_level", "privguard.threat_type", "privguard.confidence_bucket", "privguard.action_verified",
    # Agent & Tool
    "privguard.tool_name", "privguard.permission_granted", "privguard.approval_required",
    # Cryptography
    "privguard.key_version", "privguard.kms_provider", "privguard.algorithm",
    # Correlation
    "privguard.request_id", "privguard.canary_name", "privguard.canary_passed",
}
```

### 4.2 Prohibited Patterns
Any attribute key matching the following regex patterns is automatically dropped:
```python
PROHIBITED_KEY_PATTERNS = [
    re.compile(r".*prompt.*", re.IGNORECASE),
    re.compile(r".*completion.*", re.IGNORECASE),
    re.compile(r".*raw.*", re.IGNORECASE),
    re.compile(r".*memory_text.*", re.IGNORECASE),
    re.compile(r".*secret.*", re.IGNORECASE),
    re.compile(r".*token.*", re.IGNORECASE),
    re.compile(r".*password.*", re.IGNORECASE),
    re.compile(r".*content.*", re.IGNORECASE),
]
```

### 4.3 Safe Span Execution Example
```python
from app.observability.tracing import trace_span

async def process_prompt(prompt: str, user_id: str):
    # Notice: Raw prompt and user_id are NOT passed to trace_span attributes
    with trace_span(
        "privguard.gateway.process",
        attributes={
            "privguard.action": "inspect_prompt",
            "http.route": "/v1/gateway/process",
            # "prompt": prompt,  <-- PROHIBITED: Dropped by sanitizer
        }
    ) as span:
        results = await analyze(prompt)
        span.set_attribute("privguard.pii_detected", len(results.pii) > 0)
        span.set_attribute("privguard.entity_count", len(results.pii))
        return results
```

## 5. Safe Exception Handling

Standard OTel span handlers often dump exception representations (`repr(e)` or `str(e)`) directly into span status descriptions. If a database or KMS operation fails, this can leak passwords or API tokens into tracing backends.

PRIVGUARD circumvents this vulnerability by setting:
```python
with trace.use_span(
    span,
    end_on_exit=True,
    record_exception=False,
    set_status_on_exception=False,
):
```
When an unhandled exception occurs, `trace_span` executes:
1. `record_safe_exception(span, exc)`:
   - Sets `privguard.error_type` to `exc.__class__.__name__`.
   - Sanitizes `str(exc)` via regex credential scrubbers.
   - Truncates the error description to 256 characters.
   - Sets status to `StatusCode.ERROR` with a generic description: `f"Error: {exc.__class__.__name__}"`.

## 6. OTLP Collector Export Configuration

In production environments, spans are exported via the OpenTelemetry Collector:

```yaml
# In compose.observability.yaml / otel-collector/config.yaml
receivers:
  otlp:
    protocols:
      grpc:
        endpoint: 0.0.0.0:4317
      http:
        endpoint: 0.0.0.0:4318

processors:
  batch:
    timeout: 1s
    send_batch_size: 256
  attributes/redact:
    actions:
      - key: http.request.body
        action: delete
      - key: http.response.body
        action: delete

exporters:
  otlp/tempo:
    endpoint: tempo:4317
    tls:
      insecure: true

service:
  pipelines:
    traces:
      receivers: [otlp]
      processors: [attributes/redact, batch]
      exporters: [otlp/tempo]
```
